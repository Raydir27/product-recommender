🧭 Development Log — Phase 2A: Text Preprocessing & Embedding Preparation

The missing data visualization confirmed a familiar pattern: title, brand, and category fields are fully populated — reassuring, since they’re core features for embedding generation. However, description, manufacturer, and country_of_origin remain patchy. These gaps hint at the next logical step for Phase 3 — synthesizing concise product blurbs using a GenAI model to fill informational voids and keep embedding representations consistent.

Price cleaning turned out to be an interesting detour. Instead of simple imputation, a KNN-based price prediction model was trained using neighboring attributes like brand, category, and material. This approach preserves local continuity in pricing — products of similar type and brand cluster around realistic ranges. The final distribution now looks smooth and credible, with a modest long-tail of premium items (mostly furniture and home décor).

Brand and category frequency plots reaffirmed a few dominant players — a mild case of brand skew, which we’ll keep in mind when analyzing bias or designing recommendation weighting. These insights also point toward the need for stratified evaluation later, so that retrieval quality isn’t dominated by a handful of high-volume brands.

After cleaning and normalization, we moved into text standardization. Each product now carries a unified text field — combined_text — merging its title, brand, description, category, material, and color. The text is de-noised (special characters stripped, whitespace unified, casing normalized) and ready for semantic embedding.

To handle long or verbose descriptions, a chunking utility was introduced (threshold = 1200 chars, overlap = 200), ensuring large product narratives are split into manageable segments for the model. Each chunk keeps a consistent uniq_id reference, allowing later reaggregation of product-level results after embedding-based retrieval.

Embedding generation was performed using Sentence-BERT (all-mpnet-base-v2), with normalization applied pre-upsert to match Pinecone’s cosine metric configuration. Each embedding vector was unit-length normalized, and the resulting index was uploaded to Pinecone under the ikarus-products-dev namespace. Batch upsert logs confirmed clean ingestion and consistent vector dimensions.

A few technical highlights from this phase:

KNN-based price imputation ensured realistic numeric recovery without distorting value ranges.

Chunked text embeddings improved representation of long-form descriptions.

Normalization for cosine similarity guarantees consistent similarity scoring in Pinecone.

Metadata fields (brand, category, material, color, etc.) were preserved for downstream filtering and analytics.

And there we go — the dataset has evolved from a patchy, uneven table into a well-structured, embedding-ready corpus. Every product now has a unified semantic fingerprint, aligned with vector search best practices.

Next up in Phase 2B:
We’ll run semantic retrieval and clustering experiments using the Pinecone index — evaluating similarity, recall@k, and deduped product-level recommendations. This will be the first tangible test of the system’s ability to “understand” product semantics rather than just keywords.
